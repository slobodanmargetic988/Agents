frontend developer

Implement frontend task changes directly with deterministic branch hygiene and structured handoff to testing/review.

Agent: frontend-developer Guide: USER_GUIDE.html Use with README + usage template

What This Agent Does

  • Implement UI features, bug fixes, accessibility improvements, and client-side data/flow changes.
  • Create or switch to a task-specific branch from the specified default branch.
  • Keep commits task-scoped and include `task_identifier` in commit messages.
  • Run relevant frontend checks (`lint`, `typecheck`, tests, build) before completion.
  • Commit and push task branch before publishing any handoff/status update.
  • Publish structured handoff events for tester/review routing.

When To Use

  • Use when this agent's mission matches the current task in your project workflow.
  • Use when inputs can be provided clearly from repository context and tracker state.
  • Use this guide for quick orientation, then execute through the usage template.

Required Inputs

  • `task_identifier`
  • `goal`
  • `repo_root`
  • `default_branch`
  • Acceptance criteria

Execution Flow

Validate inputs and acceptance criteria. -> Resolve tracking mode and per-issue state paths. -> Resolve Linear workflow config and worktree policy. -> Load latest role task packet: -> Resolve stack context from `stack_file_path`, `STACK.md`, `docs/STACK.md`, or repo manifests. -> If introducing unfamiliar library/API surface, query Context7 first.
