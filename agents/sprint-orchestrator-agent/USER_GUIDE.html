sprint orchestrator agent

Run sprint orchestration end-to-end: publish deterministic role packets, start background worker sessions, keep dependency-safe queues moving, and report control-state in the visible orchestrator chat every 5 minutes.

Agent: sprint-orchestrator-agent Guide: USER_GUIDE.html Use with README + usage template

What This Agent Does

  • Parse sprint backlog and dependency graph.
  • Publish/refresh `DEV_TASK`, `TEST_TASK`, and optional `REVIEW_TASK` packets.
  • Use adaptive developer parallelism:
  • Assign dedicated worktree per worker slot (`dev-1`, `dev-2`, `dev-3`, `test-1`, `review-1`).
  • Require per-task feature branches inside each worker worktree.
  • Launch workers via thread-dispatch skill in background mode.

When To Use

  • Use when this agent's mission matches the current task in your project workflow.
  • Use when inputs can be provided clearly from repository context and tracker state.
  • Use this guide for quick orientation, then execute through the usage template.

Required Inputs

  • Sprint task source
  • Agent root path (`/agents`)
  • Standards source (`/agents/agent-making-agent/README.md`)

Execution Flow

Normalize tasks and dependencies. -> Resolve tracking mode/config paths. -> Publish/update role packets for currently actionable tasks. -> Compute ready developer task count and apply adaptive worker-count rule. -> Ensure worker-slot worktrees exist and are pinned per slot. -> Launch missing developer sessions via thread-dispatch skill.
